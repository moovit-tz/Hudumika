### What the Stocky production screens add

The order form separates component-source warehouse from finished-goods destination, allows a BOM choice, and shows priority, planned dates, quantity, output batch and expiry. The detail shows lifecycle, output and yield, batch, actual versus planned cost and shop-floor time. Materials show required, issued, consumed, batches used, on-hand, shortfall and cost. Routing shows work centre, operator, operation, status, time and labour. Quality has an inspection entry point. Costing separates materials, labour and overhead, plus scrap and good output. The screen describes cost per good unit on a completed order. Confirm Hudumika's costing policies before encoding that rule.

Planning explains net need using demand, stock, inbound supply and safety stock and labels acceptance as creating a draft. Combine that pattern with the reorder queue's supplier lead-time signal. Make each recommendation explainable at a warehouse and date. Distinguish sales velocity estimates from dated requirement calculations and avoid counting the same demand twice. ## Hudumika implementation anchors

- FinOps already exposes POS, procurement and production entry points. Start with the current inventory catalog/counts/stock, finance routes, budgets, bank reconciliation, fixed assets and production/quality services before proposing schema changes.
- Tuma already exposes parcels, agents, fleet and settlement. Compare those surfaces and existing routes before choosing how sales and parcels link. Tracking owns fleet/trip telemetry and operational vehicle history.
- Gereji already exposes job cards, vehicles, estimates, warranty and an existing rental surface. CRM already exposes customers, leads, deals/quotes, saved views, scoring, assignment and targets. NexusHR already exposes recruiting, shifts, time, payroll and staff assets.
- Respect Hudumika's explicit tenant predicates, tenant context and same-tenant reference validation. Use existing roles, entitlements, transaction conventions, shared types, app shells and design components. Make every posted stock or money transition retry-safe.
- Sequence priorities are an implementation recommendation. Validate with existing usage and test tenants, especially for offline POS, landed-cost capitalization, payment integrations, wallets, clinics, schools and field-specific variants.
