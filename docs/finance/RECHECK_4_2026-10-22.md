## Fresh results and remaining transaction timing issue

- Initial run: **42 passed, 3 failed** across 45 tests. P1 integrity (16) and payment integrity (13) passed. Outbox had 9 passes/2 failures; lifecycle probes had 4 passes/1 failure.
- Rerun of outbox plus probes: **15 passed, 1 failed**. All 11 outbox tests passed; the same immediate full-credit status assertion failed. Do not treat the initial outbox failures as a confirmed deterministic application defect, or conceal them behind the successful rerun.
- A focused later run of the credit/void case passed (1 passed, 4 deliberately skipped by the name filter). That is evidence of timing sensitivity, not a blanket acceptance pass.

**P1 — Success is sent before the transaction commits.** The credit-note route calls `reply.status(201).send(cn)` inside the `withTenant` transaction callback. HTTP delivery can finish before the outer transaction commits. The status helper is implemented, but immediate read-after-write observations are not reliable.

Fresh diagnostic evidence: immediately after a successful TZS 100 full-credit response, a new tenant-scoped transaction read the source invoice as `Unpaid` and found **zero visible credit_note_lines** for the returned credit id. A subsequent status read saw the committed `Credited` value. The first two runs failed the immediate-status assertion; a later filtered run passed. This explains why the new helper can be correct while the API-level acceptance is intermittent.

Required: return a plain result from the transaction callback, await successful commit, then send HTTP success outside the transaction. Apply the same check to credit void and other financial handlers with this response pattern. Add permanent tests that assert immediately visible committed records/status and no success response on commit failure. Do not solve this by adding frontend sleeps.

The changed-rate credit rejection and source-rate full USD credit/zero-AR cases passed. Sub-unit-rate settlement and partial-credit/payment/void status cases also passed. The local full-credit/void lifecycle is not certified as reliably synchronous until the transaction acknowledgement issue is fixed.
