## Milestone 3 — ANGA RFQ + quote engine (done, live-verified)

## Real bug found: ANGA PartsOS was entitlement-gated behind a key nothing ever granted (fixed)

- User-reported symptom: "the Gereji app isn't opening." Investigation found the base garage module (vehicles/job-cards/estimates/warranty/insurance) and its API were healthy — dev servers up, routes registered, `/gereji/*` routed correctly, no typecheck/build errors. The actual fault was narrower but total: **every one of the 10 ANGA PartsOS pages built in Milestones 2-5 (parts/customers/suppliers/locations, RFQs/quotes, AOG cases, goods receipts/stock units/rate-cards/hire-reservations) was gated behind the `gereji.anga` entitlement sub-key — and no migration, ever, in any milestone, granted that key to any package tier.** Confirmed by querying the live dev DB's `package_features` table directly: the base `gereji` key is granted to `professional`/`finance`/`scale`/`enterprise`/`business-tzs`/`scale-tzs`/`automotive-tzs`, but `gereji.anga` was completely absent from every row.
- Every ANGA page's data-load (`apiFetch(...).then(...).finally(() => setLoading(false))`, no `.catch()`) swallows the resulting 403 silently — the list just renders its normal empty state forever, with no visible error. Only the create-dialog actions (which do have try/catch + `showAlert`) would have surfaced a "plan does not include this feature" error on an actual attempt to use it. The main demo/SuperAdmin tenant (`Hudumika Workspaces`, enterprise plan) is exactly this case: base Gereji worked, all of ANGA silently didn't.
- Fixed with migration `748_gereji_anga_entitlement_grant.sql`, granting `gereji.anga` to `scale`/`enterprise` (named tiers) and `scale-tzs`/`automotive-tzs` (TZS tiers) — the same tier set already used for the sibling sub-feature key `gereji.warranty` (migrations 672/676), not the wider set the base `gereji` key reaches.
- **Live-verified** with two disposable test tenants via `app.inject()`: a tenant on `enterprise` plan now gets `200 {"parts":[]}` from `GET /v1/gereji/anga/parts` (previously 403); a tenant on `starter` (which was never meant to carry this key, matching the `gereji.warranty` precedent) still correctly gets `403 PLAN_UPGRADE_REQUIRED`, confirming the fix opens exactly the intended tiers and nothing else.
