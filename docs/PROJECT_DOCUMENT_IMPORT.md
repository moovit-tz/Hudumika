# Create projects from documents

Open `/projects/new`, choose related tender documents and annexes, and select **Prepare project details**. Choose a project suggestion, review and edit its details, then select **Create project**. Unrelated tenders are suggested separately; nothing is saved until the user creates the project.

Supported uploads: PDF, Word `.doc` and `.docx`, and Excel `.xlsx`. Limits: eight files, 15 MB per file, 30 MB per request, 300,000 extracted characters per request. PDF reading is bounded to 150 pages and each document to 200,000 characters. Shortened documents and unreadable pages produce coverage warnings. Scanned PDFs, including scanned pages inside otherwise text-based PDFs, use the platform's configured document-scanning service. Only unreadable pages are sent for scanning, and their results are merged with the original page numbers. A scanning response that omits requested page markers is rejected rather than silently losing pages. Without configured scanning, unreadable pages are reported for manual review.

The suggested brief includes a description, classification, location, stated project dates and amounts, client, tender reference, submission deadline and instructions, scope, deliverables, requirements, review points, missing information, tags, and supporting passages. Tender submission dates are kept separate from project completion dates. Blank bidder/specimen fields and unspecified prices remain unknown. Uploaded document instructions are treated as source material, not assistant commands.

`POST /v1/project-os/document-analysis` requires authentication and both Projects and AI entitlements, refuses external customer accounts, and uses the existing workspace/platform AI credentials and credit controls. Model output is schema-validated; quotations must match source text and PDF page citations. Unused uploads are reported. File hashes and names accompany the suggestions.

Reviewed briefs are stored in `projects.custom_fields.document_brief` through the existing project creation API and displayed on the project overview. Original related files are attached through the existing Cloud upload API to the shared Business Records drive, rather than a personal drive. Applicable Cloud storage permissions are required. If attaching originals fails, the created project remains available. The creation page lists remaining files and offers a retry that skips uploads already confirmed successful. Keep the page open to retry; after leaving it, use the project's Files section. Creation is not repeated.
