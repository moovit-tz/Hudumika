08 — Security Architecture

Zero-Trust Model

Every request is authenticated. Every action is authorized at app scope. Every query is filtered by workspace_id. No implicit trust anywhere in the stack.

App-Scoped JWT Payload

Token carries per-app roles:

{ workspace_id, email,
  apps: {
   clearance: "OFFICER",
   finops: "VIEWER",
   fleet: "DRIVER"
  }
}

Each service reads only its own scope. A Tracking API call from an unauthenticated oneSite embed uses a scoped read-only token — not the user's full JWT.

Workspace Data Isolation

Every table has workspace_id. Every query is wrapped in withTenant(). Cross-workspace leakage is structurally impossible — not just policy-enforced. PostgreSQL RLS provides a second enforcement layer even if application code has a bug.

Adaptive Authentication

OneID credit score drives MFA requirements:

Score ≥ 700 → frictionless
Score 500–699 → OTP step-up
Score below 500 → biometric re-verify

Fraud signal or new device → forced re-auth regardless of score. Moovit platform APIs use separate service tokens — not user JWTs.

Key Rotation (JWKS)

OneID issues RS256 JWTs. Private key never leaves OneID. All other services hold only the public key fetched from JWKS endpoint. Key rotation requires no app restarts — new keys picked up automatically on next JWKS fetch cycle.

Append-Only Audit Log

Every write operation — create, update, delete, role change, login, token issue, geofence trigger — is recorded in workspace_events as an immutable audit entry. Tamper-evident by structure. Queryable via Admin Console.

Instant Revocation

When onePI fires employee.offboarded, OneID revokes all active tokens for that user immediately. Redis session store allows sub-second revocation across all running service instances simultaneously. Also unassigns any active fleet vehicles.
