How to use this

The order of authority when two sources disagree.

  1. The user's own words. An explicit instruction outranks everything below.
  2. The running code. apps/web/src/index.css and apps/web/src/components/ui/ are the system. If this document and the code disagree, the code is right and this document is stale — fix the document.
  3. CLAUDE.md and AGENTS.md. Authoritative for the component mapping and the tenant-isolation rule.
  4. This document. Everything else.

Rule

Conform the other build to this system. Do not adjust this system to accommodate the other build. If a screen you are porting needs something the library does not have, add a primitive that matches the bar described in Surfaces & overlays — do not introduce a second shadow scale, radius scale, or headless-UI library.

There is a live, interactive catalogue of every component at /admin/components (apps/web/src/pages/ComponentShowcase.tsx). Open it before building anything from scratch; the thing you need usually already exists.

The brand token is not a colour you know

The single most common way this system gets broken.

The primary brand colour lives in a custom property named --teal. It has not held a teal for some time — the shipped default is #e8461a, an orange. The name is historical. Its value is set platform-wide by a SuperAdmin, and per-tenant, through /admin/design-system (apps/web/src/hooks/useDesignSystem.ts), which injects a <style> tag at runtime computing --teal, --teal-l and --teal-m from one source colour.

Trap

Never hardcode a brand hex, and never infer the hue from the token name. A tenant who switches their platform theme must see every surface follow. Any literal #e8461a, teal-500, or rgb(232,70,26) you write is a bug that will not show up until someone changes their brand colour.

Breaks on theme change

<div style={{ background: '#fef0ec',
              border: '1px solid #fdd5c8' }}>
<span className="text-teal-600">Cleared</span>

Follows the live theme

<div style={{ background: 'var(--teal-l)',
              border: '1px solid var(--teal-m)' }}>
<Badge variant="brand">Cleared</Badge>

Control sizing

One height per surface, from one token. Not per element.

Fields and buttons on a given screen must be the same height as each other. The failure mode is unglamorous and extremely common: heights get set inline, per element, as a page grows. One real form in this codebase accumulated seven different control heights — 32, 34, 36, 38, 40, 42 and 44px — none of them wrong on their own, all of them wrong together.

Seven sizes waiting to happen

<input className="input-field"
  style={{ height: 38, fontSize: 13 }} />
<input className="input-field"
  style={{ height: 40, fontSize: 13.5 }} />
<button className="btn">Save</button>
<!-- button is 42px: padding, not height -->

One token, one size

.surface { --ctl-h: 44px; }
.surface .input-field,
.surface .btn,
.surface button[role="combobox"],
.surface [data-slot="select-trigger"] {
  height: var(--ctl-h);
  border-radius: var(--r-sm);
  padding-top: 0; padding-bottom: 0;
}
@media (max-width:700px){
  .surface { --ctl-h: 46px; }
}

Rule

  • Height comes from a --ctl-h custom property on the surface, never from an inline style={{ height }}.
  • Radius comes from --r-sm. .input-field and .btn already read it, so only height needs correcting.
  • Touch targets grow on small screens (44px → 46px). They do not shrink.
  • An inline height beats any stylesheet rule. Remove the inline value — do not fight it with !important.

Component mapping

What you would reach for → what this platform uses instead. Authoritative in CLAUDE.md.

FeaturedIcon takes the icon as children, plus variant (brand / gray / success / warning / error / info), size (sm–xl) and shape (square / circle). Badge uses the same semantic names and renders a soft tint with matching-hue text — a background tint, never a solid fill.

Trap

Radix SelectItem cannot carry an empty-string value. Use a sentinel such as '__none__' and translate to and from '' at the value/onChange boundary. Combobox has no such restriction.

Reference

Button, Input and Textarea exist and are polished, but most of the app still uses the legacy .btn / .input-field CSS classes. Prefer the ui/ versions in new code. Do not embark on retrofitting old call sites unless you are already changing them.

Surfaces & overlays

Every floating surface shares one visual bar. Match it or you have made a second design system.

Popover, Select, DropdownMenu, ContextMenu, HoverCard, Menubar and Combobox content all render through Radix popper portals and share:

rounded-xl
border border-border/50
bg-popover/95
backdrop-blur-md
ring-1 ring-black/5 dark:ring-white/10
shadow-[0_8px_28px_rgba(0,0,0,.14),0_2px_6px_rgba(0,0,0,.06)]

index.css carries a global rule pinning portal content to var(--font), because portals escape the app's font inheritance. If you add a new floating primitive, match this bar exactly rather than inventing a new shadow or radius.

Trap

Radix's popper wrapper carries an inline min-width: max-content. A dropdown with no explicit width therefore grows to its longest row and escapes its container. Pin it to the trigger:

<PopoverContent className="w-(--radix-popover-trigger-width) max-h-80 overflow-y-auto p-1.5">

Reference

This system is Radix + Tailwind. If a visual reference you are matching uses a different headless-UI library, reproduce its look on top of Radix. Importing its source means two portal, focus-trap and keyboard-navigation systems fighting each other.

Soft tints

Use the derived tokens. Never hand-roll a color-mix() percentage.

Every semantic hue ships with a -l light-tint companion, and the brand also has -m for tint borders. These are computed from the live brand colour, so FeaturedIcon and Badge pick up a tenant's theme automatically.

Drifts from the rest of the app

background: color-mix(in srgb,
            var(--teal) 8%, transparent);
border: 1px solid color-mix(in srgb,
            var(--teal) 22%, transparent);

Canonical tint

background: var(--teal-l);
border: 1px solid var(--teal-m);

A hand-picked percentage looks plausible in isolation and drifts visibly once it sits next to a component that used the token — and drifts further the moment a tenant switches preset. This applies to every app on the platform, including ones added later.

Both themes

Dark is a first-class palette, not an inversion.

Dark mode is driven by [data-theme="dark"] on the root element, which redefines the tokens. Because components read tokens rather than literals, a correctly built component needs no dark-specific code at all.

Rule

  • Style through tokens. Do not write component rules inside a dark-mode selector.
  • In dark, --white is #111218 — a raised surface, not white. Read the token name as its role, not its colour.
  • Borders in dark are translucent (rgba(255,255,255,.07)), so they sit correctly on any surface beneath them.

Motion

One flagship transition, a small set of named keyframes, and three duration tokens. Nothing else.

The theme change

Switching light and dark is the platform's signature motion: a circular wave that expands from the point you clicked. It is built on the View Transitions API in apps/web/src/lib/theme.ts and it is the only place the app animates a full-page state change.

PropertyValueWhy
Shapecircle(0px) → circle(endRadius)Clip-path on ::view-transition-new(root)
Originevent.clientX / clientYThe wave starts under the user's finger, not at a fixed corner
Radiushypot(max(x, w−x), max(y, h−y))Distance to the furthest corner, so the wave always finishes covering the viewport
Duration480msLong enough to read as one gesture across a full screen
Easingcubic-bezier(.4, 0, .2, 1)The same curve as --ease
Layeringold z-index 1, new z-index 9999The incoming theme wipes over the outgoing one

Rule

Call toggleThemeWithAnimation(event) — never set data-theme directly. The helper already handles the three cases you would otherwise miss: browsers without View Transitions, a user with prefers-reduced-motion: reduce, and a toggle fired with no pointer event (it falls back to the trigger's own centre, then the top-right). All three apply the theme instantly rather than degrading to a half-animation.

import { toggleThemeWithAnimation } from '@/lib/theme';

<button onClick={e => toggleThemeWithAnimation(e)} aria-label="Toggle theme">

// Setting a specific theme, still animated:
toggleThemeWithAnimation(e, /* explicitDark */ true);

Trap

Dark mode is the presence of the attribute, not a value: light removes data-theme entirely rather than setting "light". Read state with getAttribute('data-theme') === 'dark', and observe changes with a MutationObserver on documentElement filtered to data-theme — a component that samples it once will not follow a toggle.

Durations

Three tokens cover everything. If a value feels like it needs to sit between them, it does not — pick the nearer one.

TokenValueUse
--dur-fast80msHover, press, colour change — feedback that must feel instant
--dur150msThe default. Popovers, disclosure, most transitions
--dur-slow300msDrawers, sheets, anything crossing a large distance
--easecubic-bezier(.4, 0, .2, 1)Every curve. There is no second easing.

All four are tenant-configurable through DesignTokens.motion, so a hardcoded 150ms becomes the one element that ignores a tenant's motion settings.

Overlay enter and exit

Radix surfaces animate through the shared utility set rather than bespoke keyframes. Every popper-based component uses the same combination, which is why they feel like one system:

The directional slide is what makes a menu appear to come from its trigger. Keep it when you add a primitive; a popover that only fades reads as unanchored.

Rule · reduced motion

Honour prefers-reduced-motion: reduce. The theme helper already checks it. For anything you add, the reduced path must reach the same end state immediately — not a shortened animation, and never a missing one that leaves the interface mid-transition.

Reference

Motion here is functional: it shows where something came from, or that work is in progress. There is no decorative, scroll-triggered or ambient animation anywhere in the product, and adding some would make the page that has it look like a different application.

Known traps

Each of these has been hit at least once here. All fail silently.

Tailwind v4 custom-property syntax

This project is on Tailwind 4.3.3. A bare custom property inside square brackets is not valid v4 syntax — it emits a declaration the browser discards, so the utility does nothing and nothing anywhere reports an error.

Silently does nothing

w-[--radix-popover-trigger-width]
max-h-[--radix-select-content-available-height]
origin-[--radix-popover-content-transform-origin]

Canonical v4

w-(--radix-popover-trigger-width)
max-h-(--radix-select-content-available-height)
origin-(--radix-popover-content-transform-origin)

This was wrong in 28 places across 17 files, which left every popover, dropdown, context menu, hover card, menubar and tooltip falling back to the popper wrapper's max-content width. w-[var(--…)] also works if you prefer it explicit.

Tokens that do not exist

--ink4 is not defined. It appears in older code. color: var(--ink4) is invalid at computed-value time, so the property is dropped and the text silently inherits its parent colour — “muted” captions render at full strength. Use --ink3. When porting a page, grep for it first.

Grid children that will not shrink

A grid column declared 1fr has an implicit min-width: auto, so wide content (a table, a long unbroken string) stretches the whole layout instead of scrolling. Use minmax(0, 1fr) — and apply the same fix inside your responsive @media blocks, which are easy to forget.

cmdk's default filter

The Command primitive filters by subsequence, so typing durb matched “Jeddah Islamic Port, Saudi Arabia” alongside “Durban”. Combobox passes a substring-ranking filter instead. If you use Command directly, pass the same filter.

Printed reports

A separate, deliberate design system for documents that leave the product.

Reports are generated as standalone documents, not screenshots of the UI. They have their own palette (--acc, --ink, --slate, --line, --tint) declared in the generated document, because they must render correctly when opened outside the app.

Rule

A forced break on a section that may be empty produces a blank sheet. Only emit the section — and its break — when it has content. Verify by counting pages in the generated PDF, not by eyeballing the preview.

Document order is fixed: cover and costing → summary with sign-off, QR and disclaimer → notes and assumptions → per-line reference tables. The working goes after the answer, and the reference pages carry a reconciliation line stating whether their rows sum to the summary total.

Truthful interfaces

These are UI rules, not policy. They change what you render.

This platform computes customs duty, tax and compliance obligations. A number that looks authoritative but is not causes a misdeclaration. Several interface patterns exist specifically to prevent that, and a ported screen must keep them.

Rule · never fabricate

No placeholder rates, sample HS codes, or invented charges — not even as a loading state or a demo fixture. A random sparkline, a hardcoded “86% confidence”, a Math.random() duration: all have shipped here and all had to be removed. Render a trend only once two real data points exist; otherwise render nothing.

Rule · suggest, never assign

Machine-derived classifications are shown as candidates a person accepts. Show the evidence alongside — which words matched, what the score means — so a wrong suggestion is visible rather than merely plausible. A confidence figure must be the actual ranking score, labelled for what it measures, never a number invented for display.

Rule · mark overrides

A user may type any rate. A typed rate is flagged as an override wherever it appears, including in exports, so it never carries the authority of a tariff-sourced one.

Rule · reconcile and surface

Where a document states its own total, check ours against it and show the result whether or not it agrees — green when it reconciles, red with the difference when it does not. “We checked and it matches” is the useful half of that message. Never resolve a discrepancy silently.

Rule · zero is a claim

Do not render 0 for something that was not computed. A zero against a charge reads as “this charge does not apply”, which is a different and load-bearing statement. Omit the line and say why.

Trap · every query

Row-level security exists on tables but does not protect data on its own. Every query needs an explicit .where('tenant_id', '=', user.tenant_id). A valid-looking id from another tenant is the realistic attack.

Migration sequence

Order matters — each step makes the next one's diff readable.

  1. Grep for the silent failures first. -[--radix, var(--ink4), hardcoded brand hexes, color-mix(, and grid-template-columns using a bare 1fr. These produce no errors, so they will not surface later — fix them before you can no longer see them.
  2. Delete inline control heights. Then add one --ctl-h per surface. Doing this before component swaps means the swaps do not inherit the mess.
  3. Swap hand-rolled controls for library components, working down the mapping table. Delete the useState / useRef / outside-click boilerplate as you go — Radix owns that behaviour, and leaving both in place gives you two open-state machines on one element.
  4. Replace literal colours with tokens, including tints. Now that components are library-based, most remaining literals are genuinely bespoke surfaces.
  5. Check dark mode. Toggle it and look. Correctly tokenised work needs no dark-specific code; anything that breaks is a literal you missed in step 4.
  6. Check the responsive range. 390px and 1500px at minimum. Confirm the page body does not scroll sideways at either.
  7. Re-check the truthful-interface rules against the ported screens. Ported code often carries fixtures and placeholder values that were acceptable in its original home.

Reference

Port screen by screen and verify each before starting the next. A single sweeping change across many files produces a diff nobody can review, and this system's failure modes are invisible rather than loud.
